# SENTINEL-S3 EXTRAS - Blocos de Comando (ataques nativos do S3, pos-PHASE 5)

Regra: um bloco por turno. So depois de PHASE 5 (plataforma + BLUE + RED basico +
USB HID/Ducky + SoftAP/portal). Tudo lab/allowlist. Capability-probe tudo que pode
faltar; nunca crashe; marque UNSUPPORTED/NOT FITTED. Build passa, escreve
EXTRA_PHASE_x_STATUS.md, PARA. Se quebrar, FIX (nao a fase seguinte).

```
CONTEXT LOCK - SENTINEL-S3 EXTRAS
Add native ESP32-S3 "other attacks" to SENTINEL-S3. Platform + BLUE + basic RED +

"Others" is NOT a second Reaver and NOT a Kali suite. It is what the silicon does
AFTER the hook: LAN as router (192.168.4.0/24 Wi-Fi, 192.168.33.0/24 USB),
IoT provisioning observation, capped 2.4GHz DoS (raw-TX probe), physical/sensor.

Allowlists on SD: bssid.txt, ssid.txt, ble.txt, responder.txt (names to spoof), espnow.txt (peers). Empty => refuse. No wildcard.

Any secret caught on air (provisioning PSK, spoof-name hit) is a LAB finding: BLUE alert + /logs only under MODE_LAB/RED. Never auto-exfil.
Global HID mutex: only ONE HID LIVE (USB HID, BLE HOGP, WiFi Duck share it).

Capability probe: g_raw_tx_ok, g_ipv6_ra_ok; external modules only with compile flag else "NOT FITTED".
Audit every RED action and every decode/replay to /logs/*.jsonl.
FORBIDDEN: real SSL strip, TLS break, cert-pinned MITM, PEAP/MSCHAPv2 catcher (hostapd-wpe),
WPS brute/pixie, on-chip WPA crack, KRACK/FragAttacks/Dragonblood, IMSI catcher, SDR, real jammer,

One phase per turn, build passes, write EXTRA_PHASE_x_STATUS.md, do not advance.
```
