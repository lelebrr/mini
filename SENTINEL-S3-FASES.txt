### 0) CONTEXT LOCK (1x, so se a IA nao tiver o master)

`
CONTEXT LOCK - SENTINEL-S3
You are building SENTINEL-S3 firmware for Waveshare ESP32-S3-Touch-AMOLED-1.8.
ESP-IDF 5.5 + BSP waveshare/esp32_s3_touch_amoled_1_8 + LVGL v9.
Board has TWO display/touch revs: rev1 SH8601+FT3168, rev2 CO5300+CST820. Support both.
MUST init AXP2101 PMU rails BEFORE display or the screen stays black.
I2C after PMU: 0x34 AXP2101, 0x38 FT3168, 0x51 PCF85063, 0x6B QMI8658, expander 0x20/0x21 may be absent.
SD via BSP (CLK=GPIO2 CMD=GPIO1 D0=GPIO3 typical). BOOT=GPIO0.
USB native S3. 16MB flash, 8MB PSRAM. Wi-Fi 2.4 only + BLE5. No 5GHz, no BT Classic, no SubGHz/NFC/IR unless optional module.
Product boots BLUE. RED is disarmed, PIN+ARM+allowlist. No malware, no bank portals, no empty-allowlist deauth, no on-device WPA crack.
Legal splash every boot. Audit log every red action.
i18n EN + pt-BR. Dark OLED UI 368x448.
Work one phase. Build must pass. Write PHASE_N_STATUS.md. Do not start the next phase.
`

### PHASE 3

`
Execute PHASE 3 now. BLUE IDS. Receive-only. No raw TX, no SoftAP portal, no HID, no RED arm.

GOAL
Detect hostile 2.4 GHz activity, log it, beep, show an alert feed, optionally write PCAP.

WIFI SNIFFER
- Promiscuous mode + channel hop 1-13, dwell ~80ms (configurable)
- Parse mgmt frames safely (bounds-checked IE parser - truncated frames must not crash)
- Write optional PCAP to /sd/pcap/wifi/YYYYMMDD-HHMMSS.pcap
  - Wireshark-openable: global header + LINKTYPE 105 (802.11) or radiotap if you can do it cleanly
  - File size cap 8MB then rotate
  - Start/stop on CAPTURE hub
- Do not promiscuous-dump forever at boot; user starts it or IDS start toggle

DETECTORS (wifi_ids.c)
1) Deauth/disassoc counter: threshold e.g. 10 frames / 5s -> alert CRITICAL
   Include SA, DA, BSSID, reason, RSSI
2) Beacon flood: unique BSSIDs or SSIDs per 5s above threshold -> alert
3) Evil twin vs baseline: same SSID as baseline, different BSSID and/or different crypto/channel/OUI -> alert HIGH
4) New AP vs baseline -> alert MED
5) Probe leakage: collect directed probe SSIDs from nearby STAs; report list (privacy audit)
6) EAPOL/EAPOL-start/PMKID observer: if seen, alert EAPOL observed and include those frames in pcap - DO NOT crack
7) Hygiene live: OPEN/WPS still flagged in inventory (already PHASE 2)
BLE DETECTORS (ble_ids.c)
1) Spam: Apple Continuity / MS Swift Pair / Google-Samsung Fast Pair style ads at high rate -> alert
2) Persistent tracker: same payload/addr-type pattern (AirTag/FindMy/Tile/SmartTag heuristics) whose RSSI stays relevant while IMU says the operator walked -> alert STALKER (heuristic, label as heuristic)
3) HID-over-GATT advertisement flags -> alert
4) New BLE vs baseline -> MED

ALERT FEED
- IDS hub: virtualized list, severity color, tap for detail
- Beep pattern by severity
- Persist /sd/log/alerts.jsonl
- HOME shows last alert
- Status bar dot when unread alerts

UNIT TESTS (host Unity or IDF tests)
- test/test_ie_parser.c
- test/test_evil_twin.c
- test/test_deauth_counter.c
- Fixtures test/frames/  (craft truncated + valid beacons)

UI CAPTURE hub becomes real: toggle sniffer, toggle pcap, show file size, drop count.

DO NOT
- Deauth TX
- Beacon spam TX
- Captive portal
- BLE advertise
- Auto-connect GATT to random devices

DoD PHASE 3
[ ] IE parser never overruns (tests)
[ ] Alerts can be generated from fixtures even if live RF is quiet
[ ] PCAP has valid global header (od/hexdump documented in STATUS)
[ ] UI live feed works
[ ] Hop does not deadlock UI
[ ] Build + tests pass
[ ] PHASE_3_STATUS.md including how to reproduce a deauth alert in lab with a second device (description only)

### PHASE 5

`
Execute PHASE 5 now. RED extras + BLUE honey. Capability-probe everything that might be missing on ESP32-S3 IDF. Never crash if unsupported.

GOAL
Each extra either WORKS or the UI shows UNSUPPORTED with the reason. Soak stability.

- Try esp_wifi_80211_tx (or current IDF equivalent) with a harmless probe-req or beacon to a lab SSID in allowlist, once
- Cache g_raw_tx_ok
- HW page and WIFI actions reflect this
- If IDF/driver rejects: disable deauth/beacon-tx permanently this boot

2) ALLOWLISTED DEAUTH (only if g_raw_tx_ok)
- WIFI detail -> action Deauth (RED+ARM)
- Target BSSID must be in allowlist
- If AP advertises PMF required: refuse with 802.11w PMF - deauth will not work
- Burst limited: N frames, then stop; thermal abort
- Audit

3) LAB BEACON SET (if g_raw_tx_ok)
- Advertise only allowlisted SSIDs, cap 5 SSIDs, cap rate, prefix optional LAB-

4) KARMA LIMITED
- Answer probe requests ONLY if the requested SSID is in allowlist
- No wildcard

- HoneySSID: beacon 2 decoy SSIDs never used in org (config: SENTINEL-HONEY-1/2). Any probe/assoc -> IDS alert

6) BadBLE
- Advertise HID-over-GATT name SENTINEL-LAB only when RED+ARMED
- Same Ducky runner as USB after pairing
- 5s connection-flood against allowlisted BLE addr (LAB DoS of own device)

7) BLE LAB SPAM GENERATOR
- MODE_LAB only, names prefix LAB-, max 5 seconds, then auto-off
- Purpose: test PHASE 3 spam detector
- Not available in RED field mode

8) USB MSC + COMPOSITE
- MSC exposes ONLY /sd/public as read-only disk

9) USB NCM/ECM lab network (if TinyUSB NCM available on this IDF)

10) OPTIONAL WEBHOOK

- Fail-soft

11) GATT WRITE
- RED+ARM+allowlisted BLE addr, operator picks characteristic in UI, sends bytes from a hex field
